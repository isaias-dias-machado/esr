# Evaluation, report and submission

## Grading weights

| # | Item | Weight |
|---|------|--------|
| 1 | Overlay network topology | 10% |
| 2 | Data flow management | 25% |
| 3 | Application control protocol | 15% |
| 4 | Streaming protocol | 10% |
| 5 | Final integrated solution | 30% |
| 6 | Intermediate assessment | 5% + 5% |

The two largest items are **flow management (25%)** and the **integrated
solution (30%)**. Requirements that are easy to postpone — dynamic join/leave,
alternative routes, multiple clients, live route updates — are exactly what
those items reward.

## Sub-items

Each of items 1–5 is judged on:

- **a. Conceptual specification** — is the design clear and justified?
- **b. Implementation quality** — does the code do what the design says?
- **c. Tests and critical appreciation** — are the tests convincing, and does
  the group reason honestly about limitations?

The final integrated solution (item 5) is also judged on:

- **d. Defence / presentation quality**
- **e. Report quality**

## Report

- Format: article, **maximum 12 pages**, LNCS style
  (<http://www.springer.com/computer/lncs?SGWID=0-164-6-793341-0>).
- Recommended structure:
  1. Introduction
  2. Solution architecture
  3. Protocol specification
     - protocol message formats
     - interactions
  4. Implementation
     - details, parameters, libraries
  5. Tests and results
  6. Conclusions and future work
